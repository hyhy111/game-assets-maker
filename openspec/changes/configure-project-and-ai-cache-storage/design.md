# Design

## Context

参见 `proposal.md` 的动机和 `specs/storage-location-management/spec.md` 的行为契约。

当前 `projects_root()` 固定返回 `data_root()/project`，而 Project、Frame、Audio、Process、BatchTrim API 会在初始化时缓存路径。本地资源服务器也以启动时的数据根为静态边界。AI 图片与视频共享一个配置根，但分别由 Seedream 和 Seedance 仓库使用；当前保存 `seedance.cache_dir` 只重建 Seedance manager，Seedream manager 和已绑定的媒体 resolver 仍可能指向旧根。因此路径变更不能作为普通字段写入后热切换。

## Goals / Non-Goals

**Goals:**

- 建立项目根与共享 AI 缓存根的统一解析边界，同时保留默认相对配置的可迁移性。
- 将保存、迁移、配置提交和重启组成可验证、可回滚的事务流程。
- 保证自定义项目根位于 `~/.gam` 外部时，项目 CRUD、处理流程和媒体预览仍使用同一根目录。
- 让失败保持旧配置和旧运行时可用，且绝不自动删除来源。

**Non-Goals:**

- 不在首版提供非空目标合并、冲突解决或旧位置自动清理。
- 不运行时热重绑所有 API、manager 和本地服务；成功迁移后通过重启统一切换。
- 不导入旧版应用配置，不探测或迁移从未发布的 `seedance-cache` 布局。
- 不改变旧版项目导入的选择范围或复制导入流程。

## Decisions

### 1. 使用独立的存储位置解析层

新增一个纯路径解析边界，接收配置值与稳定 `data_root`，输出规范化的项目根和 AI 缓存根。默认项目值为 `project`，默认 AI 缓存值仍为 `cache`；相对值只相对于 `data_root` 解析，绝不相对于启动工作目录解析。

项目目录配置作为应用级存储设置保存；现有 AI 缓存配置在本 change 内继续兼容当前配置读取，避免把位置迁移与无关配置格式迁移绑在一起。组合根 API 在启动时解析一次位置并注入 Project、Frame、Audio、Process、BatchTrim、Seedream、Seedance 与媒体服务，消除各模块自行猜测根目录的并行实现。测试或 CLI 的显式根覆盖仍具有更高优先级。

备选方案是让 `data_paths.py` 直接读取应用配置，但这会形成 `app_config` 与 `data_paths` 的反向依赖和隐藏 I/O，因此不采用。

### 2. 设置草稿分离配置值与展示值

后端设置读取结果同时提供持久配置值和解析后的只读绝对路径。前端目录字段显示解析路径，选择目录后只更新草稿；普通加载或保存不得把默认相对值改写为绝对值。

保存时后端重新解析并比较规范化路径，前端比较只用于即时提示，不能作为权威判断。这样 `cache` 与 `~/.gam/cache` 等价时不会触发迁移。

### 3. 由应用级 StorageMigrationCoordinator 负责迁移

新增应用级协调器，而不是把复制逻辑塞入 Seedance 设置 API。协调器接收当前配置、完整设置草稿和需要变更的位置，并按以下顺序执行：

1. 获取进程内迁移互斥锁，拒绝重复保存或迁移。
2. 解析并规范化所有来源与目标，计算真正发生变化的位置。
3. 查询 Process、BatchTrim、Seedream 和 Seedance 的活动写入状态；存在活动写入时失败退出。
4. 验证目标不存在或为空、可写、空间足够、与来源不存在相同/祖先/后代关系，且符号链接不会逃逸目标边界。
5. 返回预检摘要供前端确认；确认请求必须携带预检标识，防止确认前状态变化后盲目执行。
6. 在目标文件系统的同级暂存目录中执行不跟随符号链接的复制。
7. 通过相对路径、普通文件数量与大小清单校验完整复制，并解析关键项目、任务和批次 JSON 元数据。
8. 将暂存目录发布为用户选择的目标根；目标原本为空时仅移除已确认仍为空的目录。
9. 两项迁移全部发布成功后，原子保存整份设置。
10. 标记当前运行时必须重启，并拒绝再进入依赖项目或 AI 缓存的功能。

若任一位置失败，协调器清理自己创建且尚未提交的暂存/目标数据，保持来源和旧配置不变。若配置写入失败，则回滚本次发布的新目标；不删除或修改来源。

备选方案是直接移动来源，但跨卷移动不是原子操作，失败回滚与断电恢复更差，因此采用复制、校验和切换。

### 4. 多目录变化共享一个配置事务

项目与 AI 缓存可以单独修改，也可以在一次保存中同时修改。协调器先完成所有选中位置的复制和校验，再一次提交包括非路径设置在内的完整草稿。任一迁移失败时，本次其他设置也不保存，前端保留 dirty 状态并显示失败阶段。

这避免出现项目路径已切换而 AI 缓存路径未切换，或其他设置看似保存但迁移被回滚的部分成功状态。

### 5. 明确两个迁移数据集

项目迁移复制项目根下的完整树，因此项目内部 `cache/`、输入引用、输出帧、音频时间线和配置都随项目迁移。元数据中的外部原视频绝对路径保持不变。

AI 缓存迁移只复制共享根下的 `ai-pic-cache` 与 `ai-video-cache`，包括批次/任务 JSON、图片、视频、缩略图、编辑输入、sidecar 和终态恢复数据。它不根据当前缓存统计值裁剪数据，也不迁移项目内部缓存。

### 6. 重启替代运行时热切换

MainApp 增加一次性重启请求状态。迁移成功后前端进入必须重启状态；用户点击“一键重启”时只请求重启并销毁主窗。现有 `closed` 清理继续负责停止本地服务器、agent server 和各 manager。`webview.start()` 返回后，主线程根据重启状态通过 `os.execv` 原位启动当前程序：冻结构建执行 `sys.executable`，源码模式执行当前 Python 的 `-m backend.main`。

原位替换避免两个实例同时使用 WebView profile、配置和缓存；也不会让 `dev_start.py` 误判后端已结束并提前终止 Vite。重启失败不回滚已成功迁移的数据和配置，用户手动再次启动即可恢复。

### 7. 本地媒体服务使用显式根映射

应用启动时将解析后的项目根作为独立受限媒体根传给资源服务，而不是假设所有项目都位于 `data_root/project`。Frame/Audio API 生成相对于项目根的受控资源标识，服务端解析后再次验证目标位于项目根内。AI 图片和视频继续通过各自 resolver 访问新的共享缓存根。

不把用户选择目录的任意父级作为通用静态服务器根，防止自定义位置扩大本地文件读取边界。

## Risks / Trade-offs

- [大型项目或 AI 缓存需要双倍临时空间且耗时较长] → 预检可用空间，提供迁移进度，并在完成前保留旧配置。
- [外部进程或第二个应用实例仍可能写入来源] → 首版明确要求关闭其他实例/CLI；进程内协调器阻止当前实例写入，后续可单独引入跨进程单实例或全局存储锁。
- [仅按文件数量与大小校验不能发现等长位翻转] → 对关键 JSON 做解析校验；复制 API 的 I/O 错误立即失败。全量哈希成本较高，首版不默认执行。
- [重启在特定打包环境失败] → 配置和数据已经安全提交，允许手动启动；分别在真实 macOS `.app` 与 Windows PyInstaller EXE 验收。
- [保留来源占用磁盘空间] → 成功提示明确旧位置；自动清理属于后续独立能力。

## Migration Plan

1. 增加默认项目目录配置和解析兼容，使未自定义用户仍解析到原 `data_root/project`，AI 缓存仍解析到原 `data_root/cache`。
2. 将所有项目与 AI 缓存消费者接到统一解析结果，并让媒体服务支持受限的外部项目根。
3. 增加预检、确认、复制校验、配置提交和回滚协调器；在故障注入测试中证明失败不改变旧配置和来源。
4. 接入设置页现有保存按钮与必须重启状态，再增加原位重启生命周期。
5. 对默认路径、单路径迁移、双路径事务、失败回滚和重启进行自动化验证，并在真实打包产物中验收。

若新版本启动时没有自定义项目配置，则继续使用原目录，不需要自动搬迁。回滚到旧版本时，旧来源仍被保留；用户可以恢复旧配置或从保留目录手动恢复。
