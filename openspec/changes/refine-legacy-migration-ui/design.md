# Design

## Context

旧项目映射目前直接使用浏览器 `<select>`，设置页的九个默认值/保留时长字段也各自使用原生 `<select>`。项目已有基于 Headless UI 的共享 `Select.vue`，但它目前只接受字符串值、没有占位文案或尺寸变体。资源库标题和旧项目映射均位于 `ProjectManager.vue`，而旧项目列表来自只读的 store 计算值。

## Goals / Non-Goals

**Goals:**

- 使用一个可复用的项目下拉控件替代本次范围内的原生下拉框。
- 在不改变设置持久化、数值类型或模型联动校验的条件下统一外观与键盘行为。
- 让映射卡片可以局部关闭，且绝不影响旧项目、导入来源或迁移草稿。

**Non-Goals:**

- 不修改后端导入、批量迁移、项目目录或 AI 缓存目录逻辑。
- 不将所有仓库页面的选择控件一并重写；本 change 仅覆盖 `ProjectManager.vue` 映射卡片和 `SeedanceSettings.vue`。
- 不将关闭状态持久化到配置、项目或浏览器存储。

## Decisions

### 1. 扩展共享选择控件而非新建页面专用实现

扩展现有项目共享下拉组件，使其支持字符串和数值 model value、占位提示、可访问名称以及与输入控件匹配的尺寸/宽度。迁移映射和设置页都将把现有选项转换为该组件所需的值/显示文案列表。

不采用继续给原生 `<select>` 加 CSS 的方案：系统下拉箭头、弹出层和高度会随平台变化，不能满足项目内一致的交互要求。

### 2. 明确保留设置页变更副作用

Seedance 模型选择仍在值更新后调用现有修正逻辑；分辨率选项继续从当前模型派生。时长、数量和保留时长在选择组件边界转换/保留为数字，避免改变 API 草稿和保存流程。

### 3. 使用页面本地可见性状态关闭映射卡片

`ProjectManager` 增加仅内存的可见性状态，作为渲染映射卡片的额外条件。关闭不触发 store action，也不清空映射草稿；重新加载或重新进入页面可重新显示未迁移的旧项目。

### 4. 保持资源库操作区布局

移除中文副标题并把 `Game Assets` 作为单一、较大的标题。保留刷新和更多菜单的 DOM、标签与事件处理，以避免影响现有导入入口。

## Risks / Trade-offs

- [共享选择组件接口扩大影响现有调用方] → 保持现有字符串 API 向后兼容，并为数值和占位行为添加聚焦测试。
- [替换原生选择后模型联动失效] → 用交互测试覆盖模型切换后合法分辨率与保存草稿。
- [关闭被误解为删除或迁移] → 按钮可访问名称与测试明确其仅关闭视图，且不调用任何数据操作。
- [旧源代码断言依赖 `<select>`] → 更新受影响测试为可观察的组件、选项和绑定行为断言，而非元素标签断言。

## Migration Plan

1. 为共享选择控件的占位、字符串/数值值和键盘交互添加测试。
2. 将映射卡片与设置页的九个下拉控件迁移到共享组件，并覆盖模型联动和数值保存。
3. 实现页面本地关闭与单一资源库标题，覆盖不触发迁移的数据安全断言。
4. 运行相关前端测试、类型检查、lint、构建与最终 diff/gate 检查。
