# Proposal

## Why

设置页当前只显示 AI 缓存配置中的相对值 `cache`，项目目录不可配置，修改 AI 缓存位置也不会迁移历史数据或让所有运行时消费者一致切换。用户需要能够看清实际存储位置，自定义项目与 AI 缓存目录，并在不丢失数据的前提下通过现有“保存”流程完成迁移和重启。

## What Changes

- 在设置页同时展示项目目录与 AI 缓存目录解析后的完整绝对路径；默认配置仍保留可迁移的相对值。
- 允许用户将项目根目录或 AI 缓存根目录改为自定义绝对目录；用户选择的目录本身即为新根目录。
- 仅在点击现有“保存”按钮时比较规范化后的新旧路径；物理路径未变化时按普通设置保存处理。
- 路径变化时先检查活动任务、目标目录、路径关系、写入权限与可用空间，再向用户说明迁移范围、旧数据保留和重启要求。
- 对所有本次修改的存储位置执行一次事务式“复制、校验、提交配置”：项目迁移包含项目内部缓存，AI 缓存迁移只包含共享根下的 `ai-pic-cache` 与 `ai-video-cache`。
- 要求迁移目标不存在或为空，不合并、不覆盖；任一迁移失败时不提交任何设置，也不重启应用。
- 迁移成功后保存整份设置，阻止继续使用旧运行时，并通过正常关闭清理后原位重启应用。
- 迁移成功后保留旧目录，首版不自动删除旧数据。

## Capabilities

### New Capabilities

- `storage-location-management`: 定义项目与 AI 缓存位置的完整路径展示、自定义目录、保存时事务迁移、安全校验、失败回滚和迁移后重启行为。

### Modified Capabilities

无。

## Impact

- 后端数据路径与应用配置解析、项目相关 API、Seedream/Seedance 缓存仓库、本地媒体服务及应用生命周期。
- 前端设置页、设置草稿与保存流程、目录选择、迁移确认/进度/错误反馈和重启交互。
- Python 与前端 API 类型、持久数据隔离及迁移测试、macOS `.app` 和 Windows PyInstaller 运行验收。
- 不改变旧版项目导入契约；旧项目识别强化继续由 `streamline-legacy-project-import` 负责。
