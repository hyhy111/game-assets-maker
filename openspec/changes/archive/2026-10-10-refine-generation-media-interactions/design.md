# Design（设计约束）

## Context

动机与范围见 `proposal.md`，行为验收以本变更的三个 delta spec 为准。以下为只读代码调查结果，不代表修复已实施或运行复现已完成：

- `SeedreamBatchDetail.vue` 已有候选单选、另存、重新生成及重试下载。另存针对当前选中成功候选，删除按钮右对齐；应移动现有另存入口，避免重复。
- `backend/api/seedream_api.py` 的编辑保存覆盖当前候选图片，并保留原始备份。现有 `get_handoff_image` 可复用当前图片路径；不应以原始备份作为参考或另存来源。
- 视频首尾帧接收器已有应用内图片拖拽协议 `application/x-gam-seedream-image`，包含任务和候选索引；系统文件拖拽与图片参考区域尚需接入。详情主图当前没有对应应用内拖拽绑定。
- 参考图公开 URL 为 `/seedream-media/.../reference`；当前详情装饰只处理候选图片 URL。重新生成回填也会使用参考图 URL。这是开发端口分离时的待验证问题线索；任务创建后缩略图仍须单独验证，不预设两个问题同因。
- 编辑器输入步长虽然是 1，但历史比例乘 100 及像素换算会产生小数，留白现允许 0。
- `ArkAudit` 当前无开关；已有规格要求每次调用记录、付费提交前持久化意图。统一设置页有草稿与统一保存流程，因此即时日志开关需要独立保存语义。
- `dev_start.py` 设置 `DEV_MODE=1`，主窗口采用此标识；数据目录的 `data_mode()` 用于存储位置，不能直接等同于运行时日志许可。

## Goals / Non-Goals

**Goals：** 复用现有候选选择、媒体路径解析、缩略图与配置持久化能力，使多个入口共享同一图片来源和替换规则；由后端最终决定文件操作和审计启用资格。

**Non-Goals：** 不增加多张参考图、网页图片下载、拖拽自动生成、批量另存、登录或积分改动；不改变已有重新生成及重试下载语义，不扩充审计字段，不重构媒体生成架构。

## Decisions

### 1. 参考复用与图片版本

使用当前选中候选的受控本地路径，将其交接给图片输入页现有参考图状态；保持已有提示词与所有参数不变。进入页面时区分“复用当前图片”与原有“重新生成回填整套参数”，避免通过原有 regenerate 分支覆盖草稿。不发起生成请求。

当前媒体文件是已保存编辑后的版本，无编辑时就是原图；详情参考、应用内拖入及另存共享这一来源。更新时重新生成缩略图或携带版本标识，避免复用旧缩略图缓存。备选做法是从原任务配置重建输入，但会覆盖现有草稿，与已确认需求冲突。

### 2. 顶部栏与打开目录

图片操作栏左侧顺序固定为创建视频、再次生成、作为参考图生图、重试下载（有资格时）；删除所在右侧分组为另存图标、目录图标、删除任务。将现有另存文字入口移动为图标入口，浅灰色、复用顶部栏尺寸及颜色/背景过渡，补足 title、可访问名称和键盘焦点。视频仅在已有另存视频之后加目录入口，不扩大为视频工具栏改版。

后端根据任务 ID 与候选索引解析当前素材文件，再打开其父目录；复用既有系统目录打开能力，使用路径参数列表而非拼接 shell 命令。不得通过反解析浏览器 URL 获得本地路径，不允许该媒体操作入口任意打开未授权路径。无本地文件禁用，执行时再次校验以处理缓存被清理等竞争情况。

备选的“打开上次另存目录”容易与当前素材脱节，且不是本次确认目标。

### 3. 预览与拖拽共享单图入口

详情参考图 URL 按现有媒体服务地址规则装饰；输入区域预览复用已有缩略图接口及状态，不直接把本地路径当浏览器可见 URL。先用本地 fixture 分别复现普通选图创建、重新生成回填、当前图片复用、编辑后复用和拖入替换，确认各链路后修复，不以一个 URL 改动代替全部验收。

沿用应用内 MIME 载荷；本地文件通过桌面 WebView 可用的文件交接及既有图片校验机制进入同一设置函数。必须验证 macOS/Windows 的实际拖入路径或受控文件内容交接；不能假定所有平台均暴露 `File.path`，也不能仅保存临时 blob URL 作为生成参考。无需新增第三方拖拽库。

图片输入区域接收唯一参考图；视频只在首/尾卡片接收，提示词文字区域不推断目标。一次多个文件全部拒绝，文案为“一次仅支持一张图片”；网页 URL 和非图片拒绝。拖入失败保留既有状态。沿用后端权威文件校验及本地媒体访问授权，不放宽访问范围。

### 4. 百分比统一归一化

对输入提交、历史回填及像素换算共享整数归一化：先四舍五入角色高度并限于 1～100，再四舍五入留白并限于 0～`100-高度`。合计超限时保留角色高度、缩减底部留白；两处输入同步显示归一化值。此顺序作为实现细节固定，避免不同入口各自修正。

编辑中的临时空值可以存在，但不得应用。持久化比例与后端布局校验继续使用现有模型，提交比例必须来自显示整数；不对旧文件批量迁移。仅修改显示格式的方案会留下隐藏小数，不能满足约束。

### 5. 审计资格、配置和即时切换

新增独立布尔配置（建议名称 `ark_audit_enabled`），缺失或非布尔值按关闭处理，使用现有配置路径与更新机制持久化。后端有效启用条件为开发启动标识 `DEV_MODE=1`、非打包运行、非安装数据模式且开关开启；前端显示基于后端暴露的资格，不能仅靠 `import.meta.env.DEV` 决定。普通源码运行未设置开发启动标识时同样强制关闭；`GAM_DATA_ROOT` 只影响路径，不授予日志许可。

统一设置页中的此开关独立即时保存，成功后更新运行中审计对象的动态判定及设置页快照；失败恢复此前有效状态。统一保存、取消草稿和存储迁移流程不得用旧快照回写该字段，也不得顺便提交其他尚未保存设置。

在统一审计边界执行开关判断，覆盖 intent、响应、下载、轮询及启动日志对账；不能只禁止部分入口。关闭时不创建、追加、轮转或补写审计文件，也不因不可写日志路径抛出付费前日志错误；已有任务响应持久化和恢复继续正常。开启后继续保留原日志白名单、轮转、关联 ID 与关键 intent 写失败阻断付费提交的行为。

切换以事件写入边界生效：调用进行中关闭会阻止其后续事件，重新开启只记录之后事件，不补写关闭区间。因此部分调用可能只有部分事件；不能从缺少日志推断调用失败、未生成或未计费。备选的“调用开始时固定开关”会在关闭后继续写入，不符合即时关闭要求。

## Risks / Trade-offs

- [现有审计规格默认记录，与新开关冲突] → 本变更完整修改两条既有 requirement，并增加开关 requirement；隐私与账号隔离条款保留。
- [配置统一保存覆盖即时开关] → 覆盖独立保存、统一保存、取消及存储设置路径，保持运行状态、持久化值和界面一致。
- [WebView 文件拖拽在不同平台表现不同] → 通过真实桌面拖入验收，平台不能验证时明确记录，不把浏览器模拟测试作为完整证明。
- [整数化改变历史布局实际尺寸] → 打开编辑器时可见归一化，应用后保存新值，旧文件不被批量改写。
- [已编辑图片沿用 URL 而预览缓存过期] → 统一刷新缩略图/版本号，并测试当前图片选择及编辑后复用。

## Migration Plan

实施阶段新增缺省关闭字段，旧配置不需要数据迁移。只在实施验证后同步主规格并归档；本阶段不修改主规格或产品代码。更新 README 中“默认记录”和安装版写日志的描述，说明仅开发模式手动开启、即时切换与不完整日志的解释边界。

回滚产品实现时同时回滚配置消费和日志资格判断，并同步恢复对应规格；保留已有图片、任务、项目及日志数据。禁止通过删除用户数据完成回滚。
