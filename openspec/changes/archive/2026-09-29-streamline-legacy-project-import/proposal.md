# 变更提案

## 背景与动机

当前旧版项目导入要求用户准确选中旧版 `project` 目录，操作门槛较高；同时导入入口以完整卡片常驻主页，占用了与日常项目管理不相称的视觉空间。需要在保持复制安全边界的前提下，让系统识别旧版应用目录中的 `project` 子目录，并将低频入口收纳为按需操作。

## 变更内容

- 导入时同时接受旧版应用目录和旧版 `project` 目录，自动解析实际项目根目录。
- 仅检查所选目录及其直接子目录 `project/`，不递归扫描磁盘或其他任意目录。
- 继续使用旧项目元数据严格校验，保持复制导入、保留源目录、同名跳过和禁止导入当前项目目录的行为。
- 从主页移除常驻的旧版项目导入卡片。
- 在动画库标题的刷新按钮旁增加“更多”菜单，并在其中提供“导入旧版项目”。
- 项目库为空时，在主要创作按钮下提供轻量的旧版项目导入文字入口。
- 导入完成后按需展示本次识别路径和导入、跳过、失败数量，不保留常驻提示区域。

## 能力

### 新增能力

- `legacy-project-import`：定义旧版项目目录识别、按需导入入口、安全复制和结果反馈行为。

### 修改能力

无。当前项目尚未建立对应的长期能力规格。

## 影响范围

- 后端旧版项目导入目录解析与返回结果：`backend/api/project_api.py`、相关类型边界。
- 前端主页入口、交互状态与国际化文案：`frontend/src/views/ProjectManager.vue`、API 类型、中文和英文语言文件。
- 后端和前端测试：父目录识别、直接选择 `project`、无效目录、当前目录拒绝、同名跳过、菜单入口和空状态入口。
- 不新增外部依赖，不改变用户数据根目录，也不移动或删除旧版源数据。
