# 技术设计

## 背景

参见 `proposal.md` 的背景与动机，以及 `specs/legacy-project-import/spec.md` 的行为契约。

当前前端从 `ProjectManager.vue` 打开目录选择器，并将结果直接传给项目 Store 和 PyWebView API。后端 `ProjectAPI.import_legacy_project_directory` 只把所选目录当作项目根目录，枚举其直接子目录并调用现有严格元数据校验。导入结果类型已经包含 `source`、`imported`、`skipped` 和 `failed`，可以继续用 `source` 表示自动解析后的实际项目根目录。

## 目标与非目标

**目标：**

- 在后端统一解析所选目录，兼容直接选择 `project` 和选择其父级旧版应用目录。
- 保留现有严格校验、暂存复制、冲突跳过和源数据保护机制。
- 将低频导入操作从常驻卡片改为按需入口，并让空项目状态仍可发现该功能。
- 复用现有 API 调用链和结果结构，限制变更面。

**非目标：**

- 不扫描桌面、下载目录、磁盘根目录或注册表来猜测旧版安装位置。
- 不递归搜索任意层级的同名 `project` 目录。
- 不导入旧版配置、缓存、凭据或其他非项目数据。
- 不把导入后的扁平旧项目自动迁移为角色/动作两级结构；现有迁移流程继续独立工作。
- 不新增全局通知框架或外部依赖。

## 技术决策

### 1. 在后端解析实际项目根目录

导入 API 继续接收一个用户选择路径。后端构造两个有序候选：

1. 所选目录本身；
2. 所选目录下名为 `project` 的直接子目录。

对候选目录枚举直接子目录，并复用 `is_legacy_import_project_dir` 判断有效项目。第一个包含有效项目的候选成为实际项目根目录和返回结果的 `source`。解析完成后再与当前项目根目录的规范化路径比较，命中时拒绝导入。

选择这一方式是因为旧版便携目录位置无法可靠预知，而限定两级候选既覆盖用户常见选择错误，也避免全盘扫描带来的性能、隐私和误导入风险。没有采用前端拼接 `project/`，因为后端才是所有调用方共享的校验边界，也能处理符号链接和规范化路径。

### 2. 目录解析和项目复制保持两个阶段

先解析并冻结实际来源及有效项目列表，再进入现有逐项目复制流程。项目复制继续使用当前项目根目录内的临时暂存目录，复制后再次执行严格校验，最后以原子重命名落盘。

这样可以避免在复制循环中反复探测候选目录，也保持单个项目失败不阻断其余项目的现有部分成功语义。解析失败返回结构化失败结果；路径不存在、实际来源等于当前项目根目录等调用错误继续通过异常拒绝。

### 3. 复用现有导入结果结构

`LegacyProjectImportResult.source` 改为始终表示后端实际识别的项目根目录。`imported`、`skipped` 和 `failed` 的结构保持不变，因此 PyWebView API、前端 API 封装和 Store 无需新增调用方法。

没有增加 `selectedSource` 字段，因为用户选择路径只用于解析，界面真正需要说明的是系统最终从哪个目录导入。若未来需要审计原始选择，再通过独立字段扩展，而不是改变 `source` 的含义。

### 4. 使用局部“更多”菜单收纳导入入口

删除主页顶部常驻导入卡片。动画库左侧栏标题区域保留刷新按钮，并在旁边增加基于现有 Headless UI 的“更多”菜单；菜单项触发现有 `importLegacyProjectDirectory` 流程。项目库为空、左侧栏尚未渲染时，在主要创作按钮下显示轻量文字入口，并复用同一处理函数。

选择局部菜单而不是放入角色详情操作区，是因为导入作用于整个项目库，不属于当前角色。没有放入视频生成设置页，因为该页面与项目数据迁移的领域不一致。

### 5. 反馈仅在导入尝试后出现

移除空闲时占位的结果区域，使用仅在导入完成或失败后渲染的局部状态提示，设置 `aria-live="polite"` 并提供关闭操作。成功或部分成功时显示实际 `source` 以及三个数量；未找到有效项目时显示明确失败原因。取消目录选择不创建提示。

该方案不引入新的全局 Toast 系统，也不会让导入说明长期占据主页。导入期间两个入口共享同一个 loading 状态，防止重复触发。

## 风险与权衡

- **风险：所选父目录同时包含有效项目子目录和 `project/`。** → 按候选顺序优先把所选目录视为用户明确选择的项目根目录，并用测试固定该确定性行为。
- **风险：名为 `project` 的无关目录被探测。** → 只有其直接子目录通过严格元数据校验时才接受，不因目录名称本身导入任何内容。
- **风险：自动解析后绕过当前项目目录保护。** → 将当前根目录比较移动到解析之后，并使用规范化路径比较。
- **风险：菜单入口在空项目状态不可见。** → 空状态提供复用同一流程的轻量入口。
- **权衡：结果提示不是全局统一通知。** → 本次保持局部实现以控制范围；若后续出现更多跨页面通知需求，再单独设计共享通知能力。

## 发布与回滚

本变更不需要数据迁移或配置迁移。发布前通过后端目录解析与复制安全测试、前端入口与文案测试以及常规类型检查和构建验证。

如需回滚，可恢复旧的前端常驻入口和后端单目录解释逻辑；已经成功复制到当前项目库的项目属于用户数据，回滚时不得自动删除或覆盖。
