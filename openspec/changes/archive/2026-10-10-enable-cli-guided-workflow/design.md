# Design

## Context

动机见 `proposal.md`。当前 `gam-agent` 已提供项目、三步处理、批量裁剪及 Seedance 任务命令；`backend/agent_control/server.py` 提供固定端口 8765 的本机控制服务，现有页面打开事件没有等待前端完成回执。媒体文件服务使用动态端口，两者职责不同。

步骤参数已由 `ProcessAPI.get_step_params` / `save_step_params` 保存到项目；CLI 当前执行路径从默认参数构建，需要改为读取保存值再应用显式覆盖。生成草稿由 `frontend/src/stores/aiCreation.ts` 管理，项目处理状态由 `stores/process.ts` 管理。图片、视频生成及缓存已有 API 和仓库，实施应复用这些入口。

本工作区存在并行的 `refine-generation-media-interactions` 变更；素材复用和生成审计相关修改需按实施时的实际代码衔接。本变更的 CLI 生成开关独立于 `ark_audit_enabled`，不修改审计策略。存储遵循 `storage-location-management` 及现有运行时根目录契约。

## Goals / Non-Goals

**Goals:** 通过现有 CLI、控制服务、后端 API 和前端 store 建立可查询、可保存、可回执的操作链；统一直接提交的后端授权边界；让中文技能指导用户检查实际素材后继续。

**Non-Goals:** 不新增生成供应商、账户或计费逻辑，不改变抠图与裁剪算法，不统一各动画 FPS，不重新推导已导出的音频帧索引，不在此变更中增加音频时间线编辑接口。规格中的功能完整覆盖本次需求，不扩展为任意 Python、文件读写或 JavaScript 执行入口。

## Decisions

### 1. 扩展现有控制服务并复用运行中的应用实例

复用本机 `AgentControlServer` 和 `AgentUIClient`，采用操作白名单及结构化 JSON 请求；媒体动态端口继续由媒体服务处理，不为控制服务新增端口扫描。控制服务保持仅本机访问约束，并校验请求类型、请求体、目标及参数。

运行中应用的操作交给其现有 API 实例执行，避免 CLI 另建生成管理器、处理队列或存储迁移状态。现有离线本地命令可保留，回执明确 `ui_sync` 未完成；生成草稿、页面跳转和 CLI 直接提交需要运行中的应用。应用运行时以其有效数据根、项目根、AI 缓存根为准，CLI 指定的不同根须明确拒绝，不能悄悄操作另一套数据。遵循迁移期间的现有写入限制。

备选方案是为 CLI 再建独立服务与全套管理器；它会产生状态竞争、根目录分歧和提交权限绕过，因此复用应用组合根。

### 2. 请求执行、保存和界面应用分别回执

请求携带唯一 `request_id` 和允许的操作名；后端保存及校验完成后，向前端发送受控事件。前端调用现有 store 和路由，在真正完成加载／修改后通过 bridge 确认。后端维护有界的待处理回执，不跨等待持有全局锁，也不阻塞 UI 线程。

响应分别说明操作结果、`persisted` 和 `ui_sync`，附项目／任务标识与实际使用参数。事件发出不能作为界面成功证据。超时返回可查询的请求状态和明确错误；调用方不得因回执超时自动重跑处理或提交。对已接受的同一请求标识返回已有状态，不能重复执行；不承诺在应用重启后以新的请求标识自动恢复未知提交。

保持现有 CLI JSON 输出约定，诊断信息走 stderr。错误区分参数无效、目标不存在、应用未运行、界面同步超时、生成授权关闭、素材缺失和提交状态未知，避免统一包装成成功。

备选方案是沿用派发事件即成功；它无法验证切页、项目加载或 store 更新，不能满足同步显示要求。

### 3. 草稿按字段合并，处理参数从保存值构建

草稿查询读取当前图片／视频 store。更新先初始化现有默认值，再在候选对象中合并显式字段，完成字段类型、枚举和本地图片可用性校验后一次性应用。省略字段保留原值，支持清空的可选引用用显式空值；非法混合更新不得部分修改草稿。参考图预览复用 `setImageInput` 及现有素材解析逻辑。

“再次生成”通过历史记录恢复草稿，包括提示词、图片及参数，并返回草稿回执。缺失引用文件明确报错，不用另一次生成补偿。

处理参数使用项目保存值加显式覆盖，后端复用现有参数校验；成功后保存合并结果并同步当前目标项目。只覆盖所选步骤的指定字段，其他步骤与未暴露字段保持原值。CLI 的 `step run` 同样采用这条构建路径。

| 步骤 | 本次支持字段 |
| --- | --- |
| 1 | `frame_interval`、`start_frame`、`end_frame` |
| 2 | `alpha_matting`、`alpha_matting_erode_size`、`alpha_matting_foreground_threshold`、`alpha_matting_background_threshold` |
| 3 | `enabled`、`green_intensity`、`feather_radius`、`min_hole_size`、`align_enabled`、`align_h`、`align_v` |

参数范围、结束帧哨兵和依赖关系从现有后端及控件核对，统一校验后在说明书记录。切页按现有路由和稳定 ID 完成；切换前后的操作绑定请求中的项目，不能污染另一个项目。

备选方案是覆盖整个草稿或使用默认参数执行；会丢失用户已调整内容，因此采用补丁合并。

### 4. CLI 命令沿用已有命名空间

在 `project`、`step`、`seedance` 等既有命令旁增补角色查询、草稿读写、素材读查与图片提交。推荐结构为 `role list`、`project list --role`、`step params get/set`、`ui navigate`、`artifacts list/read`，图片／视频草稿放在 `seedream draft`／`seedance draft` 下，已有 `seedance create` 保留名称并执行新权限校验。

文件或 JSON 输入用于补丁及复杂参数，支持机器读取回执；不要求用户手抄参数到命令行。实现时以统一 help 和契约测试固定最终选项。现有命令兼容，但直接提交新增默认关闭的授权要求，应在 help、错误消息和中文说明书中注明。

### 5. 生成开关由 GUI 确认，提交由后端实时校验

新增 `cli_generation_enabled` 配置，缺失、格式错误或不可读取均按关闭处理。统一设置页的“允许 CLI 提交 AI 生成任务”在尝试开启时弹窗说明：CLI 可直接提交、可能消耗费用或额度、Agent 首次在当前对话使用仍需确认。确认后才调用专用持久化入口；取消或保存失败保持原状态。关闭立即持久化，启动不弹窗。

配置入口不能被 CLI 控制操作或普通配置补丁绕过启用确认；普通设置保存需防止旧草稿覆盖即时开关状态。每次 CLI 图片／视频远程提交前读取当前有效值，包含现有 `seedance create` 路径；调用既有生成源选择、输入校验及提交 API。手动 GUI 发送沿用原行为。开关关闭不取消既有任务，也不限制读取、查询、下载、草稿和本地处理。

当前对话首次确认由技能负责，明确用户回答后记入当前对话状态；后续同一对话沿用，用户撤销后停止提交，新对话重新确认。不得把配置开启、过去另一对话授权或沉默当成当前对话确认。它不被伪装成后端可验证的用户身份令牌。

备选方案是仅在技能中约束提交；直接调用 CLI 可绕过，因此后端必须独立校验。另一备选是每次提交重复弹窗；与用户确认一次的要求不符。

### 6. 本地素材通过现有仓库发现，读取采用安全投影

按角色、项目、步骤和生成任务关联已有文件，返回稳定 ID、实际绝对路径、类型、存在状态及必要元数据，支持过滤和分页。不新增持久化的全局索引。根目录从有效存储配置解析；项目已记录的合法外部输入可作为授权输入引用，任意路径与符号链接越界不得借此放行。

过程素材包括源文件、各步输出、保存参数、音频时间线及裁剪结果；AI 素材包括已缓存输入、输出、提示词、请求参数与安全的响应内容。响应采用明确投影和脱敏，排除 API key、授权头、账号凭据及敏感临时链接。二进制返回可访问本地文件及类型，不将整段媒体塞入 JSON。

缓存不存在、已清理或文件缺失时返回明确状态，不把远程 URL 当成本地成功，也不自动发起新的远程请求。用于参考图的素材必须是可读取的已保存文件；编辑器未保存状态不冒充文件。

备选方案是任意目录递归扫描并原样输出缓存 JSON；其范围和敏感内容不可控，因此按仓库与项目关联读取。

### 7. 批量裁剪和 Godot 按实际输出衔接

角色与动画列表返回稳定 ID，项目名或动作名不作为唯一标识。统一包围盒与逐帧紧致裁剪复用现有多选 API，保持当前隐藏帧和源目录语义。返回真实成功／失败明细和最终帧目录，存在的 `_frame_data.json`、`_audio_timeline.json` 及音频文件位置；缺少清单返回空值，不能猜测目录。

`gam-export` 接收最终序列帧目录，普通 PNG 使用自然排序与默认偏移，偏移帧使用既有清单。音频采用最终零基 `placement_frame`，不重新按原视频时间计算。不同动画允许不同 FPS，音频保持正常播放速度；切换动画或停止时默认立即停止音频。现有导出行为及验证脚本优先复用。

### 8. 中文技能按职责拆分，说明书引用实际功能

`gam-workflow` 按当前输入和目标选择下一步，默认软件已安装，每次只问一个问题；读取状态、执行操作、展示或检查实际结果后继续。它调用提示词技能、CLI 与导出技能，不另建 UI 自动化工作流。

`gam-guide` 的入口短小，按需加载功能、参数、配置与 CLI 参考文档；说明中写清用途、条件、范围／默认值、调整效果、依赖和常见错误。参数说明从实施时实际校验与控件提取，区分预览 FPS、提取间隔、恢复草稿与提交、两种裁剪方式。

gam 系列 frontmatter 的描述及操作说明使用中文，命令和代码标识保留原文。新技能遵循仓库现有技能来源约定；实施前检查 `.agents/skills` 的忽略及部署关系，避免只有临时副本。`gam-export` 先确认共享库真实来源，保留生成器及验证资源，再调整中文说明；共享部署通过既有管理工具执行并记录范围，不直接覆盖不明副本。

备选方案是一份技能塞入完整说明书、提示词和导出实现；会产生重复维护和上下文负担，因此拆分入口和参考资料。

## Risks / Trade-offs

- [前端异步切页或加载失败] → 请求绑定目标 ID，等待完成回执；保存与显示分开报告，并提供状态查询。
- [CLI 和 GUI 同时改同一项目] → 运行时复用同一 API 实例，候选补丁校验后合并最新状态；避免另建后台队列及默认值覆盖。
- [回执超时引发重复远程提交] → 同一请求标识查询已有结果；未知状态停止自动重试，以既有任务查询核实。
- [旧配置或设置草稿覆盖开关] → 缺省关闭、专用持久化入口、提交实时读取，并测试旧配置和交错保存。
- [缓存暴露敏感数据或路径越界] → 安全字段投影、实际路径边界检查、脱敏测试；说明书不展示真实凭据。
- [跨变更的素材复用和审计代码冲突] → 实施前检查并行变更，只衔接已存在能力，保持 CLI 开关独立。
- [中文文档与实现漂移] → 参数表、help、错误及技能参考在同一实施任务中更新，以真实运行验收核对。
- [静态测试无法证明桌面同步与听感] → 增加真实桌面交互验收，Godot 运行检查与视觉／听觉检查分别记录。

## Migration Plan

1. 保留无开关的既有配置，首次加载采用关闭默认值；不移动项目或 AI 缓存，不执行存储迁移。
2. 先实现接口、授权及回执契约，再接前端，随后补齐 CLI 和技能参考，集中验收。
3. 已有 `seedance create` 增加明确关闭错误和开启入口说明；本地命令、查询及桌面手动发送继续使用原契约。
4. 回滚产品代码可忽略新增配置键，恢复原有能力；用户素材和项目保存参数不删改。回滚可能恢复旧 CLI 无开关提交行为，需在回滚记录注明。
5. 技能部署单独核对来源并备份，回滚仅恢复本次修改文件及其部署，不处理其他技能或并行变更。
