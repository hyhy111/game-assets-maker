# 角色与动画重命名

## 调整原因

动画库目前没有角色和动画的重命名入口，名称填错后无法在列表中直接修改。动画卡片的删除按钮还需要悬浮才能看到，这次一并改为常显。

## 本次改动

- 角色列表名称左对齐，不显示动画数量，右侧增加常显的三点菜单，动画卡片在删除图标左侧增加同样的入口。菜单沿用动画库标题旁的样式，仅包含「重命名」。
- 点击重命名后打开应用内弹窗，预填原名称，提供保存、取消和就地错误提示。菜单和弹窗均使用应用自绘样式。
- 重命名同步更新目录、项目 ID 和元数据。角色改名影响其下全部动画，动画改名只影响当前动画；同名目标不覆盖、不合并。
- 改名后同步角色选择、动画勾选和预览状态，刷新或重新进入编辑器仍能读取原素材。
- 动画卡片的删除图标改为常显，保留悬浮变红和现有删除确认。

## 涉及能力

### 新增能力

- `library-item-renaming`，定义角色与动画菜单、重命名交互、名称校验、数据同步和删除按钮的可见性。

### 调整已有能力

无。现有 `selection-control-consistency` 约束迁移映射和设置页的选项控件，本次增加的是动画库操作菜单。旧项目迁移入口和规则保持原样。

## 影响范围

前端涉及 `ProjectManager.vue`、项目 store、API 封装、桥接类型及中英文文案。后端涉及 `ProjectAPI` 的重命名操作、`backend/main.py` 的桥接入口和必要的写入互斥。

项目仍使用当前配置的存储根，不引入依赖，不改动图片处理算法。已有 `update_project` 的元数据更新行为保留，界面重命名使用新接口。历史裁剪成品和生成任务记录不做全库改写；后续读取项目与新裁剪使用新名称。

## 范围约定

「未迁移」是旧项目的虚拟分组，不提供角色重命名；其中单个旧动画允许改名，保持原有平铺结构。这是兼容旧数据的默认处理方式。

本次只增加重命名，不增加移动、复制、合并或批量改名，也不新增 CLI 重命名命令。
