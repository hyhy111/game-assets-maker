# 角色与动画重命名设计

## 现状

改动动机见 `proposal.md`。当前项目使用 `项目根/角色/动画` 目录，项目 ID 由角色名和动画名拼接；旧项目仍使用平铺目录。`ProjectAPI.get_projects()` 从目录读取角色和动画，卡片优先显示 `project.action`。已有 `update_project()` 只修改 `project_name`，无法完成这次界面重命名，而且其名称冲突判断是全局范围。

`ProjectManager.vue` 已使用 Headless UI 的 `Menu` 绘制动画库菜单，并使用 `Dialog` 绘制确认弹窗。角色行本身是按钮，角色列表有滚动裁切，动画卡片有 `overflow-hidden`。直接嵌入菜单会遇到按钮嵌套和菜单裁切。

项目 store 当前保存 `activeLibraryRole` 和 `libraryViewState`。页面按项目 ID 保存勾选、预览帧、请求和计时器，改名后必须同步这些引用。相关文件已有未提交修改，实施时在当前版本上衔接，不替换或回退这些修改。

## 目标与边界

设计要让名称、目录和界面引用一起更新，且普通失败后仍能找回原素材。保留现有目录结构和元数据格式，不为此次功能引入数据库或永久不变的内部 ID。

已有 `update_project()` 继续服务原有元数据更新。旧 ID 不建立重定向；外部调用方重新列出项目后使用新 ID。历史生成任务的交接记录作为当时记录保留，不声称旧 ID 仍可打开项目。历史裁剪成品不重新命名文件或重写导出清单；角色目录内的历史成品会随父目录搬移，之后的新裁剪使用新名称。

本次不修改全库任意路径字符串。只有当前项目元数据中明确表示本项目文件的路径才按目录边界更新，项目外的源视频和共享 AI 缓存路径保持原值。

## 设计决定

### 复用现有菜单和弹窗

两个入口使用 `MoreVertical` 图标及现有 `Menu` 样式，只放一项「重命名」。不引入原生下拉框或原生输入对话框，也不为单个菜单项增加新的 UI 依赖。

角色行调整为外层布局容器、角色选择按钮和菜单按钮并列。选择区继续承担当前角色语义和键盘焦点，菜单按钮只打开菜单。动画操作区阻止点击和键盘事件冒泡到卡片，不触发卡片的 Enter 打开行为。

菜单面板传送到页面顶层，以触发按钮的可视位置定位，处理窗口边缘。列表滚动或视口变化时关闭菜单，避免面板留在旧位置。菜单继续使用现有组件的键盘导航和焦点恢复。相比移除卡片的裁切样式，这样可以保留当前预览外观。

删除按钮移除父容器的透明度限制，保留灰色默认态和 `hover:bg-danger/15 hover:text-danger`。不移动角色详情区已有的删除角色按钮。

### 共用一个重命名弹窗

页面保存目标类型、原名称、原角色或项目 ID、新名称、提交状态和错误。角色与动画共用弹窗结构，标题分别为「重命名角色」和「重命名动画」，字段标签使用「角色名称」和「动画名称」。

打开后选中原名称。Enter 提交，取消和 Esc 在未提交时关闭；提交期间禁用重复提交和关闭，等待明确结果。失败保留输入并聚焦错误相关字段；成功后关闭，焦点回到对应的新菜单入口。如果搜索过滤导致入口消失，则回到搜索框。

前端校验用于及时提示，后端始终重新校验。中文和英文都补齐文案，后端错误在 API 封装处转成界面可读提示。

### 新增专门的重命名操作

在 `ProjectAPI` 增加角色重命名和动画重命名方法，通过 `backend/main.py` 暴露，并补齐前端 API、桥接声明和返回类型。建议接口名为 `rename_role(role, new_name)` 与 `rename_project(project_id, new_name)`。

成功结果包含新项目数据、最新角色摘要以及每个受影响项目的旧 ID 到新 ID 映射。角色改名返回全部受影响动画，动画改名只返回一个。未改变名称时返回一致的成功结构，不搬动目录。

接口在当前注入的 `_projects_root` 下操作。名称先去首尾空白，再检查空值、点目录、控制字符、路径分隔符、Windows 不支持的字符与设备名、结尾点或空格、保留分组名。拒绝不合法输入，不沿用创建时把非法字符替换成下划线的宽松行为。校验目标父目录、解析后路径边界和符号链接，拒绝越出配置项目根的操作。

角色与目标目录按 `casefold()` 判断冲突；动画只比较同角色目录，旧动画比较项目根同层目录。普通角色还需检查根目录中同名旧项目或其他目录，动画也不能覆盖同角色中的裁剪输出目录。与自身名称完全相同视为未改动；仅修改自身大小写时通过唯一临时名中转，以兼容默认大小写不敏感的文件系统。

### 目录与元数据作为一次操作完成

角色改名先枚举真实动画项目，预读受影响元数据并保存原始内容，然后在同一父目录内改名整个角色目录。动画改名只改目标动画目录；旧动画仍在平铺层级，不借此执行迁移。

元数据同步更新 `role`、`action`、`project_name`。角色改名保留原动画名和显示名，动画改名才同步新的动画名与显示名。已知项目内绝对路径按旧目录到新目录转换；相对路径和项目外路径保留。音频时间线的项目相对路径继续沿用，加载时重新生成媒体 URL。

元数据采用临时文件加替换写入。角色存在多个动画时，任一元数据提交失败就恢复已更新文件并把目录改回原名；大小写中转使用同样的恢复路径。正常执行错误需可恢复，断电或进程被强制结束不承诺跨文件事务保证。

只有全部步骤完成才返回成功。恢复也失败时，返回包含实际保留目录的明确错误，不删除原数据，不把可恢复文件当作垃圾清理。

### 防止重命名与项目写入交错

`ProcessAPI.has_active_writes()` 能识别等待与运行中的任务，`BatchTrimAPI.has_active_writes()` 能识别裁剪活动，现有应用组合入口也集中注入项目根。这些活动查询可以复用，但单次查询本身不能防止查询后立刻开始写入。

在应用组合处协调一把共享锁，让重命名的活动检查和目录更新，与新处理任务登记、裁剪开始及项目创建或迁移的关键入口互斥。已有异步处理不在全程持锁；先登记活动，再释放锁，改名看到活动后直接拒绝。同步写入在关键区间内持锁。涉及项目目录的交接、音频保存和参数保存也必须遵守同一约定，不能只禁用前端按钮。

先采用保守规则，有本地项目写入时拒绝重命名，提示任务结束后重试，不中断任务。存储迁移进行中或已要求重启时同样拒绝改名。复用现有活动信息和组合入口，不趁机重构任务调度系统。

### 用后端结果更新界面

成功后先停止受影响预览，再依据返回映射更新 `projects`、`roles`、`currentProject`、`activeLibraryRole` 和已勾选 ID。以一次完整状态更新提交，避免角色列表的监听器在中间态回退到第一个角色。

对受影响预览清除旧帧、索引和计时器，并让旧异步请求失效。后续按新项目 ID 获取帧，不通过替换旧 URL 字符串猜路径。播放器若仍持有受影响项目的旧帧，也在下次加载前清空。

搜索词保持原样。结果因改名消失时沿用现有无匹配状态，保留搜索框；清空后显示新名称。不改名的其他角色保持选择。分页保留有效页码，只有超出新页数时收敛到最后一页。

旧动画改名时同步迁移草稿的项目键，保留用户已填写的目标角色和动画，避免草稿被当成新项目重置。虚拟「未迁移」分组不显示角色菜单，后端也明确拒绝对它改名。

## 风险与处理

- 目录已经改名但元数据写入失败，会出现名称不一致。保存原始元数据并在异常时恢复，测试覆盖角色内第二个动画写入失败的情况。
- 旧预览请求可能在改名后才返回。使用请求版本或等价标记丢弃旧响应，验证列表不再使用旧 URL。
- 大小写改名在 macOS、Windows 与大小写敏感文件系统上行为不同。用临时名中转，并分别检查自身改大小写和与其他目标冲突。
- 保守的写入互斥可能暂时阻止与目标无关的改名。先保证文件不会在处理途中搬走，后续有实际需要再细化到单项目。
- 外部程序保存的旧项目 ID 和绝对路径会失效。接口明确返回新 ID，应用内刷新引用；外部文件不做全盘搜索替换。

## 发布与恢复

没有启动时批量迁移，已有项目保持原样，只有用户保存时才改名。版本回退后仍能读取符合原有角色与动画目录结构的项目，但外部保存的旧 ID 不会自动恢复。

验证使用临时项目根和小型素材，不修改用户项目。自动化检查完成后，在真实桌面中验收菜单位置、边缘弹出、键盘交互、删除常显，以及重启后的预览和编辑；将这部分证据与隔离测试分开报告。
