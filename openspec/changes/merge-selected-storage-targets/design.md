# Design

## Context

现有迁移协调器已经使用目标同级暂存、清单校验和配置事务，但仅能将完整暂存目录重命名为不存在或空的目标，预检因而拒绝所有非空目标。参见 `proposal.md` 与 `storage-location-management` 的 delta spec。

## Goals / Non-Goals

**Goals:**

- 在保留用户预存目标内容的前提下，将无冲突的项目或 AI 缓存数据安全迁入所选目录。
- 让冲突在复制前可预测、可定位，且任何失败都不污染用户原有内容。
- 仅调整设置面板的存储控件排列，不改变其保存和选择入口。

**Non-Goals:**

- 不提供覆盖、重命名、交互式冲突解决或自动合并同名目录。
- 不改变目录配置格式、迁移数据边界、来源保留或迁移后的重启流程。
- 不将目录选择器的行为改为选择父目录。

## Decisions

### 1. 以迁移范围的相对路径检测冲突

预检将待迁移范围展开为相对于目标根的路径集合：项目迁移使用完整项目树，AI 缓存迁移仅使用 `ai-pic-cache` 与 `ai-video-cache`。若目标中任一相对路径已存在，不论其类型是普通文件、目录或符号链接，均作为冲突拒绝。该策略不会猜测文件是否“相同”，也不会把同名目录视为可安全合并。

替代方案是按内容哈希跳过相同文件或递归合并同名目录；两者都会把用户选择的同名数据悄悄纳入迁移语义，超出已确认的“仅冲突时提示”。

### 2. 保留暂存校验，按顶层无冲突条目发布到已有目标

继续先将完整范围复制到目标同级暂存目录并校验清单和 JSON。目标不存在时保持现有整目录原子发布；目标已存在时，在发布前重新确认暂存条目与目标无冲突，再逐个移动暂存中的顶层条目进入目标。发布记录每个本次新增的路径，以支持逆序回滚。

替代方案是直接向用户目录复制；这会使复制中断与校验失败留下难以区分的半成品，无法满足不污染既有内容的约束。

### 3. 回滚仅处理本次发布的条目

已有目标的合并发布失败，或另一个位置迁移/配置提交失败时，只移除本次已移动到该目标的条目；不再递归删除整个目标根。为防止确认后外部进程抢占名字，发布时再次检查每个目标路径；出现晚到冲突时触发完整事务回滚。

### 4. 前端使用单列容器

将存储位置面板的两个字段容器从响应式两列改为单列；字段内部仍保留路径输入框与“选择文件夹”按钮在宽屏同排、小屏换行的现有行为。

## Risks / Trade-offs

- [预检与发布之间目标内容变化] → 发布前再次进行无覆盖检查，并将晚到冲突作为可回滚失败。
- [回滚删除了用户在迁移期间新建的同名条目] → 只回滚本进程成功移动、已记录的路径；不递归删除整个用户目标。
- [跨文件系统时移动暂存内容失败] → 暂存目录仍位于目标同级，维持同一文件系统；失败保留来源并执行已发布条目的回滚。
- [同名目录含不同子内容本可技术合并] → 按已确认策略将其视为冲突，避免无声混合用户数据。

## Migration Plan

1. 为非空无冲突目标、文件/目录/链接冲突、双位置事务回滚及晚到冲突补充迁移和设置 API 测试。
2. 实现预检冲突清单、已有目标的受跟踪发布及最小回滚。
3. 调整设置页为单列并增加布局断言。
4. 运行聚焦 Python/前端测试及静态检查；验证最终 diff 与 Jev gate。
