# 功能、参数与配置

## 制作流程

图片创建支持提示词和一张参考图；视频创建支持提示词、首帧、可选尾帧及界面现有生成参数。首帧决定角色外观和视角，视频提示词描述动作及终态。再次生成恢复原任务草稿；准备草稿不会提交新 AI 任务。已有图片的保存编辑版本可继续作为参考或视频首帧，未保存的画布编辑不能当成本地文件使用。

角色包含若干动画，项目 ID 通常是 `角色/动作`；同名动作通过角色区分。创建项目后先提取视频帧，再去背景，最后处理挖空与对齐。步骤 2 需要步骤 1 的帧，步骤 3 需要步骤 2 的透明帧。重新抽帧会使下游旧处理结果失效。

裁剪支持统一包围盒（global，各帧统一画布）和逐帧紧致（individual，帧尺寸可变并保存偏移）。使用实际返回的目录，通常位于角色下的 `batch-trim[-n]/动作/`。隐藏帧沿用软件规则；失败或部分成功要逐动画查看回执。裁剪结果含音频时读取 `_audio_timeline.json`，逐帧偏移读取 `_frame_data.json`。

## 三步处理参数

下表默认值用于新项目，当前动画以 `step get` 返回值为准。补丁只修改明确字段，其他参数保持保存值；执行使用保存值加本次明确覆盖。

| 步骤 | 参数 | 默认 | 范围或约定 | 作用与观察 |
|---|---|---:|---|---|
| 1 | frame_interval | 1 | 正整数 | 每隔 N 帧提取一次；增大减少帧数，检查动作是否跳跃 |
| 1 | start_frame | 0 | 非负整数 | 从零基索引开始提取；检查动作起势是否被截掉 |
| 1 | end_frame | -1 | -1 为视频末尾，或不小于起始索引 | 软件新建项目可写入实际末帧；检查收招与循环衔接 |
| 2 | alpha_matting | true | 布尔 | 改善半透明边缘，观察毛发、细线和边缘残色 |
| 2 | alpha_matting_erode_size | 5 | 0–20 | 增大收缩参与 Matting 的边界，过大可能损失细节 |
| 2 | alpha_matting_background_threshold | 120 | 0–255，须小于前景阈值 | 调整确定背景区，观察残色与主体缺损 |
| 2 | alpha_matting_foreground_threshold | 240 | 100–250，须大于背景阈值 | 调整确定前景区，观察主体边界和透明过渡 |
| 3 | enabled | true | 布尔 | 启用挖空；不含绿幕孔洞时可关闭 |
| 3 | green_intensity | 3 | 1–5 | 数值越大检测越暗沉的绿色；角色自带绿色可能被误删 |
| 3 | feather_radius | 3 | 0–10 像素 | 柔化孔洞边缘，过大可能产生模糊透明边 |
| 3 | min_hole_size | 5 | 0–500 像素面积 | 忽略小孔；增大可减少细碎误删，可能保留小残色 |
| 3 | align_enabled | false | 布尔 | 总对齐开关；关闭时子开关不执行对齐 |
| 3 | align_h | false | 布尔 | 水平居中，检查原地动画抖动及有意横向位移 |
| 3 | align_v | false | 布尔 | 底部对齐，检查落脚与跳跃是否保持预期 |
| 各步 | fps | 步骤 1 为 30，步骤 2／3 为 10 | CLI 1–60 | 预览播放速度；与提取间隔是不同参数 |

背景模型沿用已安装的 u2net 与软件模型就绪检查。参数开关不会下载或提交 AI 生成任务。CLI 生成授权关闭时，本地三步处理仍可用。

## 音频与 Godot

在软件处理阶段调整音频切片和触发帧，再由裁剪导出映射到最终帧序列。`placement_frame` 是最终序列的零基帧索引，`source_placement_frame` 仅用于溯源。向用户表达时可换成“第 N 张图片”，读取元数据时保持原索引。

动画之间可使用不同 FPS。播放到目标索引时触发声音，声音按自身原速播放；改变动画 FPS 不应改变音调。停止、暂停或切换动作时默认立即停止当前音效。Godot 的无界面检查证明资源与脚本可运行，实际帧序、锚点和听感还需在场景中检查。

## 配置与本地数据

安装模式默认把可写数据放在 `~/.gam`，包括项目、配置、缓存、日志和模型；项目和 AI 缓存可由设置修改到自定义目录。查询 `gam-agent doctor` 和当前存储设置，使用实际有效根。`GAM_DATA_ROOT`、`GAM_DATA_MODE`、`GAM_CONFIG` 用于显式运行环境，开发目录不代表安装数据目录。

存储迁移后若应用要求重启，先重启再继续 CLI 控制；CLI 根与应用根不同会返回 ROOT_MISMATCH。旧项目导入采用复制方式，源目录保留，既有目标不能被覆盖。

AI 创建需要对应生成来源的配置。当前可用来源为自定义 API Key；界面尚未支持的平台来源不会自动回退到 API Key。凭据在软件设置中维护，说明与命令输出不展示密钥、账号令牌或临时下载链接。

“允许 CLI 提交 AI 生成任务”默认关闭，仅用户尝试开启时出现说明并确认，启动不弹窗。此开关立即单独保存；关闭阻止后续 CLI 提交，但不取消已提交任务，也不阻止用户手动发送、查询、下载和本地处理。Agent 还需遵循 `gam-workflow` 的当前对话首次提交确认。

## 再次生成与重试下载

“再次生成”恢复提示词、参考图和参数到草稿，仍由用户发送；CLI 的 draft restore 也只回填草稿。直接创建新的 AI 任务属于一次新的生成，需遵循生成授权。

“重试下载”位于图片候选结果或视频详情的下载失败提示中，使用已有任务保存的结果地址下载，不调用 AI 生成接口。图片仅支持 download_failed、保存了有效地址且地址未过期的候选；视频须远端 succeeded 且保存了结果地址。URL_EXPIRED、缺失响应／地址和 SUBMISSION_UNKNOWN 不能通过重新生成自动补偿，应先核对原任务。当前新增 CLI 没有专用重试下载命令，可导航到对应详情由用户操作。
