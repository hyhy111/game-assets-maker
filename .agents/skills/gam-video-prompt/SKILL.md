# gam-video-prompt：游戏角色动作动画提示词助手

为 gam 编写游戏角色动作视频提示词，供后续抽帧、抠图、对齐和制作动画素材使用。以单个角色的首帧为主要依据，尾帧可选。工作范围是撰写和优化提示词。

用户要求将提示词或参考图填入gam时，使用 [gam-cli](../gam-cli/SKILL.md) 写入相应草稿并读取核对；时长可采用下方给出的建议，其他未指定参数保持原值。仅要求写提示词时直接输出文本。

用户询问如何开始生成、使用 ForFuner AI 或配置自定义 Key 时，阅读 [AI 生成方式与配置](../gam-guide/references/ai-generation-setup.md)，优先推荐新用户登录使用 ForFuner AI，并按其选择给出配置步骤。仅要求提示词时保持文本输出；账号、Key 和价格说明放在提示词正文之外。

## 图片引用语法

提示词用 `@图片1` 引用必填首帧，提供尾帧时用 `@图片2` 引用尾帧；未提供尾帧时只使用 `@图片1`。使用“@图片1 中的角色”或“@图片2 的姿态”等完整指代，避免标记直接紧接动作动词。

角色的外观、服装、配色、武器与视角由图片承载。提示词直接描述被引用角色的动作，省去“以首帧中的角色开始动作”及静态外观复述；需要保持或改变的特征按实际要求补充。填入 gam 时，将引用的图片分别写入 `first_frame` 和可选 `last_frame` 字段。

## 从首帧与动作开始

1. 确认哪个角色图是首帧，读取其角色造型、比例、服装、武器、持握方式、视角和背景。已有信息直接使用；未看到角色图时不要声称已识别图中细节，可以先按已知设定写出待配图的提示词。
2. 确认要做的动作、朝向和结束方式。只有缺失会改变动画内容的信息才需要先询问，例如未指定动作、首尾图角色不一致、移动方向含糊，或循环与结束状态冲突。
3. 风格、视角和角色设计优先继承首帧。项目偏好为 2D 手绘动画；首帧已有其他明确风格时保持一致。角色静态信息由首帧承载，提示词重点描述随时间变化的动作。
4. 用“@图片1 中的角色……”直接开始动作描述。提供尾帧时，说明动作如何自然衔接到“@图片2 的姿态”，其终点优先于默认结束方式。用于不同方向的角色图应各生成独立动画。
5. 若首帧含多个角色或多个视图，先明确本次动画的单一主体，建议使用对应方向的单角色完整图作为首帧。

## 单镜头与角色一致性

- 全程保持同一固定机位、投影、俯仰角和取景尺度。直接继承首帧的侧视、斜俯视、正面、背面或其他方向。
- 多阶段动作仍在同一连续镜头内完成，用“先……随后……最后……”连接动作阶段。默认每段视频只承载一个动作或用户明确要求的一组连招。
- 保持同一角色的头身比例、配色、服装、肢体数量、武器造型和持握关系。只有动作所需的身体部位发生运动，道具随持握和惯性运动。
- 角色和武器全程完整可见，取景为动作预留空间；画面尺度稳定，避免通过缩放角色容纳跳跃或挥击。
- 原地移动循环以画面中心为根部位置，双脚交替迈步、身体自然起伏。跳跃允许竖直位移，翻滚、滑铲等允许动作所需的有限位移；不要同时要求这些动作的身体和脚底位置完全锁死。
- 八向移动需说明角色朝向画面右上、右下、上、下等方向，并保持相应的首帧视角。背面动作继续展示背面，避免为展示表情自动转到正面。只有用户要求转身时才改变朝向。
- 左右方向优先用画面方位表述，持武器的手沿用首帧，不把画面右侧误写成角色右手。镜像会同时反转装备位置和标记；用户需要严格保留不对称设计时，分别制作对应方向。

## 描述动作与节奏

写清关键肢体如何运动、动作方向、幅度、速度、重心和武器位置，并说明前后阶段的承接。根据角色实际身体结构描述脚、爪、翅膀、尾巴等，避免凭空添加肢体。

- 待机与行走采用连续、清楚的节奏；奔跑、攻击、跳跃和翻滚保留用户需要的力度与速度，不统一弱化成缓慢小动作。
- 单次攻击可写成准备、发力、收招；跳跃可写成屈膝、蹬地、腾空、下落、落地缓冲。用动作阶段表达顺序，不机械规定每个阶段的精确秒数。
- 衣摆、披风、耳朵和尾巴随身体运动和惯性产生适度次级运动，保持与主动作的因果关系，避免遮住关键肢体或武器。
- 默认只生成这个角色的动作。需要命中目标、蹬墙或其他接触物时，先判断是否能写成角色单独的动作演示；依赖真实接触关系而用户未说明时，再确认是否需要接触物。
- 明确的表情要求用可见细节表达；背面或小尺寸角色优先依靠姿态表达，避免补写不可见的面部变化。

## 循环与终点

- 待机、行走、奔跑通常采用循环：描述稳定的运动周期，以及结尾与开头相容的姿态、步态相位和运动趋势。若首帧为静止站立而用户需要连续行走循环，说明生成片段包含站立到行走的过渡，完整步态周期可供后续截取，不要每走几步就停回站立。
- 跳跃、攻击、施法、受击通常演示一次，完成后恢复待机；只有用户要求循环时才重复。
- 死亡动作完成后保持倒地或用户指定的终态，不自动站起，也不强制循环。
- 首尾姿势相近只能作为循环目标；提示词不能保证实际输出无缝循环，衔接效果需要检查生成片段。

## 抠图与光效约束

- 视频提示词必须明确使用均匀、纯色的亮绿色背景，并在全程保持稳定；这是当前版本的要求，不继承其他背景色。
- 用户明确需要其他背景色时，在提示词正文之外告知：“当前 gam 的去背流程针对绿色背景优化，后续会更新支持去除其他背景色；本次素材提示词仍使用绿色背景。”不把版本说明写入生成提示词，也不自行推荐其他背景色替代绿幕。
- 首帧或可选尾帧不是绿底时，先说明上述限制，引导用户通过 `gam-pic-prompt` 准备保留角色设计的绿底参考图，再继续视频草稿；不直接沿用非绿底图片，也不承诺仅靠视频提示词就能稳定换底。
- 角色含与绿幕相近的绿色时，保留已有角色配色并告知同色区域可能被误删，背景仍使用绿色；不擅自改色或承诺能完整保留同色细节。
- 背景全程颜色均匀、静止，角色与武器外缘清楚，主体自身的明暗和材质延续首帧。
- 默认制作纯角色动作：避免新增泛光、外缘光晕、魔法光芒、粒子、火花、烟尘、拖尾、冲击波和背景投影。以挥动、蓄力、发力、后坐、衣物惯性表现力量，施法通过身体与法杖动作表现。
- 首帧已有且完全位于主体内部的发光细节可以维持稳定，但不扩大到轮廓外或演变成动态特效。
- 单一角色的干净动作画面，不默认添加场景、字幕、标记或装饰性元素。用户明确提出与抠图冲突的光效时，指出影响并优先建议制作纯动作素材，将效果单独处理。

## 动画时长与声音

- 根据动作完整性和节奏，从 4、5、6 秒中选择一个具体建议时长 n；用户已指定合法时长时沿用该值。提示词正文用动作阶段表达节奏；总时长仅作为正文外的建议，在正文后另起一段写“建议动画长度为 n 秒”，替换 n 为具体数字。后续用户要求通过 CLI 填入该提示词的草稿时，可将建议时长写入 `duration` 参数；用户明确指定的时长优先。
- 提示词中明确“无需背景音乐，仅保留与角色动作同步的音效”。按实际动作描述脚步、衣物摩擦、武器挥动或落地等声音，声音事件与动作对应；碰撞或命中音效仅用于确实存在接触的动作。

## 输出方式

使用用户当前交流的语言，默认直接给一份可复制的自然语言提示词，用普通段落展示，不使用代码块。只在用户要求多动作时分别列出提示词。复杂连招可以按阶段分段，阶段始终属于同一个连续镜头。

优先组织为：图片引用与动作阶段、节奏 → 朝向、取景和结束状态 → 音效要求 → 简短的背景与轮廓约束。必要的约束清楚写一次，避免反复堆叠禁止词、固定兜底包或影视画质修饰。没有固定字数限制，也不输出平台名称或参数表；图片引用沿用上述 `@图片N` 语法。

输出前检查：图片编号与实际素材对应、动作可读、首帧视角和角色一致、机位固定、身体运动与位置要求相容、循环或终态合理、正文外的建议时长为 4、5、6 秒之一、仅有动作音效且无背景音乐、首尾参考图与提示词均使用均匀纯亮绿色背景、抠图边缘干净。用户要求其他背景色时，确认已在正文之外说明后续更新支持的计划。检查过程留在内部；仅在存在关键假设或冲突时简短说明。

提示词输出、修改或草稿填写完成后，按 [gam-workflow 的“阶段结束后的下一步引导”](../gam-workflow/SKILL.md#阶段结束后的下一步引导) 提供简短引导：优先让用户自行预览生成结果并提示本次动作的检查重点，由 agent 协助查看作为次选项。
