# 起点与授权走查

| 用户起点 | 先收集的证据 | 下一步 |
|---|---|---|
| “做一只史莱姆” | 游戏视角与素材用途；缺视角时只问视角 | 写图像提示词、准备草稿，由用户发送 |
| “让这张图吼叫” | 实际角色图、朝向与动作终态 | 写首帧驱动动作提示词，填写视频草稿 |
| “这个视频抠图后有绿色孔洞” | 项目 ID、步骤 2 透明帧和步骤 3 当前参数 | 检查角色绿色与孔洞区别，调整挖空参数后本地执行 |

| 情境 | 行为 |
|---|---|
| 默认关闭、用户想自动创建 | 准备草稿，说明设置入口；等待gam开启确认 |
| 开关开启、当前对话第一次 | 说明内容、数量及费用可能性，等待用户明确确认 |
| 用户尚未回答或拒绝 | 保持草稿，不提交 |
| 当前对话已经确认 | 查最新开关后直接提交后续任务 |
| 新对话或无法证明确认属于当前对话 | 重新确认 |
| 用户撤销或开关关闭 | 停止新提交；仍可查询旧任务和本地处理 |
| 提交超时或 SUBMISSION_UNKNOWN | 查原 request_id、任务记录与目录，保持不重试 |
| 已保存任务但 ui_sync=pending | 报告任务 ID 和待同步状态，先恢复查询，不新建任务 |

没有看到生成图片、视频或过程帧时，说明缺少质量证据，先读取可用缓存媒体；任务 completed 只证明处理完成。

只有原始视频、尚无项目时，确认角色与动作名称后执行 `gam-agent project create --video /绝对路径/视频.mp4 --role 角色 --action 动作`，记录返回的项目 ID。先读取步骤 1 参数并检查源帧，再执行提取；后续按步骤 2／3 顺序处理，无须登录或开启 CLI 生成。

## 下一步引导示例

按当前阶段选用并改写，沿用实际素材和用户已确认的选择：

- 视频提示词已写好：确认动作描述没问题后，下一步我可以把它和选定的首帧填入gam的视频生成草稿，需要你检查并手动发送；也可以先调整动作、朝向或结束姿势。
- 草稿已填写并读取核对：草稿已填好，你可以在 gam 中检查提示词、参考图和生成参数后手动发送。生成后先自行查看结果；视频可重点关注动作是否流畅、角色和武器是否完整入画，以及结束姿势是否符合预期。确认满意后可以继续制作素材，需要协助判断时，我也可以帮你查看。
- 视频提示词已修改并写入草稿：请在 gam 检查草稿并手动发送。生成后建议你自行预览，重点看起手是否利落、挥击姿态是否清楚、收招是否自然；如果有拿不准的地方，也可以让我协助查看。
- 已查看图片候选：你可以先选定一张角色图。如果角色占画面太大，可以在 gam 的图片生成详情打开“图片编辑”，缩小角色并留出动作空间，保存后再作为视频首帧；确认比例合适后，我会根据它编写动作提示词。如果造型或画风还需要调整，也可以先修改图片草稿。
- 已查看生成视频：确认这段动作符合预期后，下一步可以建立角色和动作项目，开始抽帧；如果动作范围或节奏需要调整，也可以先修改视频草稿。
- 进入步骤 01 准备抽帧：选好画面帧范围和间隔后，可以展开“音效轨”，选取并试听要保留的声音，再点击“创建 Audio Clip”或“自动创建”，拖动片段调整声音的触发位置；这些片段后续可以通过 `gam-export` 随动画一起导出到 Godot。不需要音效时直接继续抽帧。
- 步骤 02/03 处理已完成：先检查实际过程帧，发现残色或孔洞时针对问题调参；异常或多余画面可以用“隐藏当前帧”排除，误操作可用“恢复上一帧”或“恢复全部”。隐藏不删除原图，会同步影响步骤 02/03 的预览与最终导出。
- 裁剪已全部完成并核对输出：下一步可将最终帧、偏移，以及裁剪结果中已核对的音效文件和 `_audio_timeline.json` 交给 `gam-export`，一起生成带音效的 Godot 动画资源；没有音频清单时只导出动画。如果裁剪边界还需要调整，可以先修改裁剪方式。

草稿仍待手动发送时，引导用户检查和发送；任务尚在运行时，引导等待或查询；质量尚未检查时，引导查看真实媒体。使用与实际进度相符的措辞，避免把准备草稿、生成完成或质量验收混为一谈。
